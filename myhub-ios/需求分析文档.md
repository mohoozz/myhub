## 1. 项目概述

### 1.1 项目背景

原 myhub 采用「Go 后端 + Flutter 客户端」的自托管全栈架构，所有存储接入、流媒体转码、内容解析、进度记录均由服务器端承担。本项目将其**重构为一款纯本地化的 iOS 原生应用**：

- **去服务器化**：不再依赖任何自托管后端。所有数据（配置、进度、收藏、书签、缓存、索引）全部保存在设备本地。
- **本地直连存储**：由 iOS 客户端**直接连接** WebDAV / SMB 等网络存储，在设备侧完成目录浏览、流式读取、解析与播放。
- **原生技术栈**：使用 Swift + SwiftUI（辅以 UIKit）构建原生体验，播放内核参考 nPlayer 的解码与缓存架构，获得全格式本地解码能力，摆脱后端实时转码。

保留原应用的四大内容模块能力：**漫画、视频、音频、小说、内置浏览器**，以及**动态**模块（动态功能后续通过对接外部 API 实现，本期预留接口与占位）。

### 1.2 项目目标

1. **纯本地应用**：无服务器端，所有数据与缓存保存在本地（沙盒 + App Group）。
2. **原生网络存储直连**：客户端直接支持 WebDAV、SMB（含 SMB2/3）等常用网络连接协议，可扩展 FTP/SFTP/NFS。
3. **全格式媒体播放**：参考 nPlayer 架构，内置解码引擎（硬解优先、软解兜底），支持网络串流下的边下边播缓存。
4. **完整内容模块**：漫画、视频、音频、小说、内置浏览器全部原生支持；动态模块预留接口（后续通过 API 接入）。
5. **进度与偏好本地持久化**：阅读/播放进度、收藏、书签、历史、设置均落本地数据库。
6. **iOS 原生体验**：SwiftUI 自适应布局（iPhone / iPad），支持手势、画中画、后台音频播放、Dynamic Island 等平台特性。

### 1.3 用户画像

单一用户（设备持有者本人），个人自用，无多租户、无账号体系。网络存储凭据由用户在应用内配置并安全存储于 Keychain。

### 1.4 与原架构的核心差异

| 维度 | 原 Flutter 全栈版 | 本 iOS 原生版 |
| --- | --- | --- |
| 后端 | Go Gin 服务器 | 无后端，纯本地 |
| 存储接入 | 后端存储适配器（Local/WebDAV/OpenList） | 客户端原生协议栈（WebDAV/SMB…） |
| 流媒体 | 后端透传 + FFmpeg HLS 转码兜底 | 设备端解码引擎（硬解/软解），无需转码 |
| 内容解析 | 后端 parser（txt/epub/zip/rar） | 设备端原生解析 |
| 数据存储 | SQLite（服务端）+ drift（客户端） | 全部本地：Core Data / SQLite + Keychain |
| 动态抓取 | 后端 AI Agent（OpenClaw） | 后续对接外部 API（本期预留） |
| 平台 | 六端跨平台 | iOS（iPhone/iPad）原生 |

### 1.5 名词定义

| 名词 | 说明 |
| --- | --- |
| 连接源（Connection） | 一个已配置的存储位置：本地沙盒目录、WebDAV、SMB 共享等 |
| 挂载点（Mount Point） | 连接源在应用内呈现的虚拟入口，如 `/NAS`, `/WebDAV-A` |
| 边下边播（Progressive Cache） | 网络串流时按需下载并缓存分片，实现秒开、拖动与断点续播 |
| 阅读进度（Progress） | 小说章节位置、漫画页码、视频/音频播放时间点的统称 |
| 动态项（Feed Item） | 一条来自外部平台的更新内容（本期预留） |

### 2.2 通用框架（IOS-001）

#### 2.2.1 导航架构

SwiftUI 采用自适应导航，随尺寸类（Size Class）切换：

| 设备形态 | 导航方式 | 说明 |
| --- | --- | --- |
| iPhone（竖屏 / Compact） | 底部 `TabView` | 阅读 / 动态 / 浏览 / 浏览器 / 设置 |
| iPad（Regular / 横屏） | `NavigationSplitView` 侧边栏 | 阅读 / 收藏 / 动态 / 浏览 / 浏览器 / 设置 |

**导航项**：
- 阅读（`books.vertical` SF Symbol）
- 收藏（`star`）
- 动态（`bolt`，本期为占位页）
- 浏览（`folder`）
- 浏览器（`globe`）
- 设置（`gearshape`）

#### 2.2.2 页面保活与全局播放

- Tab 切换保持各页面状态（SwiftUI `@StateObject` / 场景持有）。
- 视频/音频播放器为独立全屏路由，不随 Tab 切换销毁。
- **迷你播放器**：全局悬浮条，跨页面存在，可展开/收起、拖拽关闭。
- 浏览器标签会话由全局 `ObservableObject` 持有，切页签不销毁。

#### 2.2.3 主题系统

**亮色**：蓝白主调——主色 `#2563eb`，页面背景 `#eef4fb`，卡片纯白。
**暗色**：纯黑背景 `#000000`，卡片 `#121212`，侧栏 `#0a0a0a`。

- 沉浸式场景（播放器、阅读器）统一纯黑背景。
- 主题（亮/暗/跟随系统）持久化到 `UserDefaults`。
- 支持 iOS 系统深浅色自动切换。

### 2.3 本地数据存储（IOS-002）

- **结构化数据**：连接源、收藏、阅读进度、书签、历史、下载任务 → Core Data（或 SQLite/GRDB）。
- **可重建缓存**：小说章节索引、编码信息 → 沙盒 `Caches`（JSON 文件或库表均可），与进度数据分离——进度不可丢，索引丢失可重扫重建。
- **偏好设置**：`UserDefaults`。
- **敏感凭据**：WebDAV/SMB 账号密码 → Keychain（`kSecClassGenericPassword`），支持生物识别（Face ID / Touch ID）保护。
- **缓存**：媒体分片缓存、缩略图、漫画解压页 → 沙盒 `Caches` 目录，受系统清理与应用配额管理。
- **数据导入导出**：支持配置（不含明文密码）导出/导入，便于迁移。

### 2.4 浏览模块（文件管理）

#### IOS-101 连接源管理

支持添加以下类型连接源，均在**客户端本地直连**：

- **本地路径**：应用沙盒 `Documents` 目录、iOS「文件」App 共享（Files/iCloud Drive via `UIDocumentPicker` / Security-Scoped Bookmark）。
- **WebDAV**：地址、账号、密码、根路径，支持 HTTPS、连接测试。
- **SMB**：服务器地址、共享名、账号/密码或访客、域（Workgroup），支持 SMB2/SMB3。
- **可扩展**：FTP / SFTP / NFS 以协议适配器形式预留。

连接源以「虚拟挂载点」呈现（如 `/NAS`、`/WebDAV-A`）；支持编辑、删除、启用/禁用、连接测试；凭据存 Keychain。

**连接状态提示**：连接测试正常显示**绿点**、异常显示**红点**；点击「连接测试」成功时提示词区分「内网 / 外网」可达情况。

#### IOS-102 文件与文件夹浏览

- 列表 / 网格视图，按名称、大小、修改时间排序；排序偏好持久化，路径显示设置缓存。
- 面包屑路径导航，当前目录内搜索；下拉刷新、空/加载/错误状态。
- 文件类型识别与图标/**封面缩略图**：音视频、漫画、图片均显示封面（浏览页与「正在阅读」页一致），视频抽帧首帧本地生成缩略图并缓存。
- **封面加载性能（重要）**：封面异步加载、失败占位、结果缓存；**封面拉取不得阻塞点击播放/进入**（避免「封面未加载完点视频卡顿严重」的问题），进入播放/阅读优先于封面加载。
- 大目录分页/懒加载，网络源结果本地缓存以加速二次进入。
- **选中/交互效果**：
  - PC/iPad：鼠标/指针 hover 有选中效果（参考「正在阅读」列表模式高亮）。
  - iOS：点击/长按某项时有明确选中态高亮。
- **iOS 侧滑返回上一级**（重要）：浏览页支持从左侧边缘滑动返回上一级目录，带过渡动画——当前目录界面滑向右侧，被划过区域露出上一级目录内容。
- **右上角 … 菜单**：菜单为圆角、带精致弹出动画（iOS 与 PC 均需美化，PC 含右键菜单）。
- **不支持预览的文件**：点击时底部拉起菜单，提供「纯文本」查看入口（打开独立纯文本界面，与小说阅读器区分）。
- **纯图片文件**：点击进入独立图片预览界面（与漫画阅读器区分），支持左右滑动 / 点击分区 / 键盘 / 浮动按钮切换上一张、下一张。
- **多平台操作**：各平台文件操作交互统一梳理——PC 右键上下文菜单，iOS/移动端长按进入多选模式（非仅弹菜单），多选操作栏按钮不得超出手机屏幕。

#### IOS-103 文件上传 / 下载

- 从本地/相册上传到 WebDAV/SMB，显示进度。
- 远端文件下载到本地沙盒（供离线播放/阅读）；**支持下载常见文件（图片、txt 等）到「文件」App / 相册**。
- **txt 在线编辑**：文本文件支持在线修改并保存回源。
- 大文件分片、断点续传（P1）；后台传输（`URLSession` background、SMB 分块）。

#### IOS-104 / 105 移动、复制、重命名

- 单选/多选后在同一连接源内移动、复制、重命名。
- 跨源移动通过设备端流式中转（边读边写，不落大临时文件）。

#### IOS-106 删除与回收站

- 删除默认进入回收站（逻辑删除，记录原路径）。
- 回收站支持：还原、彻底删除、清空、自动清理（可配保留天数，默认 30 天）。
- 本地/远端：回收站为挂载点下 `.trash` 目录（远端不支持时降级为本地元数据标记 + 真实删除确认）。

#### IOS-107 文件收藏

- 文件/文件夹可标记收藏、取消；收藏记录持久化本地。
- 收藏为独立模块页，网格/列表切换，按类型图标展示，卡片整体可点击。
- 点击收藏条目直接进入对应播放器/阅读器；与浏览页星标双向同步。

### 2.5 阅读模块

#### IOS-201 / IOS-202 视频 / 音频播放（参考 nPlayer 架构）

**核心内核**：参考 nPlayer 的「全格式解码 + 网络直连 + 边下边播」架构，采用**双引擎解码策略**：

| 层级 | 说明 |
| --- | --- |
| 硬件解码（优先） | `AVPlayer` / `VideoToolbox` 处理 H.264/H.265/AVC/HEVC 等主流格式，省电流畅 |
| 软件解码（兜底） | 基于 FFmpeg（`libavcodec`/`libavformat`）或 `MobileVLCKit` 处理 mkv/rmvb/avi/flv/wmv/ts 等非原生格式 |
| 自动切换 | 探测容器/编码，原生可播走硬解，否则回退软解；用户可在设置中强制硬解/软解 |

- **全格式支持**：无需转码，直接播放 mp4/mkv/avi/mov/flv/rmvb/ts/webm 等及各类音轨。
- **网络直连播放**：直接对 WebDAV/SMB 上的文件流式播放（详见 IOS-203 缓存）。
- **播放能力**：
  - 记录播放进度，下次自动续播。
  - 倍速（0.5x ~ 3.0x）。
  - **字幕**：内嵌字幕轨选择；外挂 srt/ass/ssa 自动匹配同名文件（含 `name.zh.srt` 语言后缀约定），样式/大小/延迟可调。
  - **音轨切换**：多音轨选择、音频增益、声道映射。
  - **音频唱片封面模式**：封面旋转动效（播放时旋转、暂停停止），封面来源同目录同名图片 / cover / folder / front / ID3 内嵌，无封面显示占位；标题/作者按「作者 - 标题」文件名解析；控制栏与视频一致。视频/音频模式按实际媒体轨校正（内嵌 albumart 不算视频轨）。
  - **纯音频播放模式**：视频可切换为「仅音频」模式（关闭画面解码、进入唱片封面 UI，节电并支持后台/锁屏播放）。
- **手势**（iPhone）：
  - 水平滑动调节进度；右侧竖滑调音量；左侧竖滑调亮度。
  - 双击左右快退/快进（默认 10s，可配）。
  - 长按倍速播放；调节时中央悬浮胶囊实时反馈（进度时间 / 音量% / 亮度% 图标 + 数值，**必须有数值显示**）。
  - **下拉进入 mini 模式**：从画面中央向下拖动进入 mini 播放器，带过渡动画。
- **iOS 音量**：音量调节必须与系统音量联动（`MPVolumeView` / 系统音量），步进 5%（非 1%）。
- **画中画（PiP）** 与 **后台音频播放**（见 IOS-602）。
- **AirPlay** 投屏（原生格式）。
- **退出与 mini 交互**：
  - 控制栏「退出」按钮为**直接退出**播放器（不进入 mini）；单独在下方功能栏提供「进入 mini」按钮。
  - mini 播放器为**悬浮式（类灵动岛 / QQ 音乐风格）**：跨页面保持、可拖拽关闭、可展开回全屏（复用同一会话不重载）。
  - mini 条在深色/浅色模式下均加**细边框**，避免与黑色背景融为一体。
- **播放器细节修正**（吸收实战经验）：
  - 起播时中央「开始按钮」与「旋转加载圈」不得重叠。
  - 暂停/播放提示图标方向必须正确（暂停显示暂停图标、播放显示播放图标）。
  - 不同分辨率视频（含竖屏视频）正确适配显示比例，不拉伸/不裁切错误。
  - 从浏览页再次点击**正在 mini 播放**的同一文件时，切换回完整播放模式。

#### IOS-203 网络串流边下边播缓存（参考 nPlayer 缓存架构）

面向 WebDAV/SMB 等网络源的流式播放缓存机制：

- **本地代理/分片缓存**：内置本地 HTTP 代理或自定义 `AVAssetResourceLoaderDelegate`，将远端 Range 请求转为分片下载并缓存到磁盘，供解码器按需读取。
- **HTTP Range / SMB 分块读取**：支持拖动进度条时定向拉取目标区间，实现秒开与快速 seek。
- **精准断点续播（重要）**：恢复历史进度时**必须直接从历史位置起播**，不得先从 0 播放再 seek（避免可见的「跳一下」）；即在首帧就绪前完成 seek 定位。
- **预读窗口**：向前预读 N 秒/N MB（可配），保证平滑播放；网络抖动时自动扩大缓冲。
- **断点续播**：已缓存分片持久化，重进同一文件复用缓存。
- **缓存策略**：LRU 淘汰、总容量上限（可配）、单文件缓存上限；「设置」中可查看与清理。
- **弱网优化**：自适应缓冲阈值、超时重试、连接复用；弱网点击文件先展示 UI 进入加载界面（见 §2.11）。

- 底部弹出「下一个：xxx」提示，5 秒倒计时自动播放，点击立即播放。

#### IOS-205 / IOS-206 小说阅读

- **txt**：设备端流式读取，本地建立章节索引（正则识别「第 x 章」等），大文件按章按需加载，不一次性读入。
- **编码检测（重要）**：自动识别 UTF-8 / GBK / Big5 / **UTF-16 LE/BE**；策略为 BOM 判定 + 无 BOM 启发式 + 码元对齐建索引 + 旧缓存编码复核自愈，避免中文乱码（纯 txt 预览与小说阅读器均适用）。
- **epub**：设备端解包（epub 即 zip），解析目录/章节/资源，按需渲染，无需后端；**epub 需做图集型（漫画）判断**，图集型 epub 提示/一键转交漫画阅读器。
- 阅读器功能：字体大小、行距、主题（日间/夜间/护眼）、翻页/滚动模式、目录跳转、亮度调节。
- 章节列表缓存（可重建派生数据，存沙盒 `Caches`）；记录每本书阅读位置。
- **进度定位锚点（重要）**：使用排版无关锚点，禁止页码/百分比等排版相关锚点——
  - **txt**：存**全局字节偏移**（一个 Int64）。恢复时直接 seek 到该字节位置，再经章节索引（各章起始字节偏移表）二分反查所在章节，**一步定位完成**（章节索引进度条/目录联动同样由偏移反查得出）。
  - **epub**：存 **(spine 序号, 段落序号, 段内字符偏移)**，排版无关；不实现完整 EPUB CFI。
- **文件指纹**：进度记录附带 `fileSize + modTime`；打开时校验指纹，文件被替换则提示并重建索引，避免跳转错乱。可附一小段上下文文本作为位置兜底找回（可选增强）。
- 正文可选思源宋体（内置字体资源）。

#### IOS-207 漫画阅读

- 支持格式：zip / cbz / rar（cbr）/ epub（图集型）。
- 设备端按需从压缩包解出单页图片，不整包解压落盘；页序自然排序（natural sort）。
- 阅读模式：单页、双页（横屏/平板自动启用，可切换从右向左/从左向右并持久化）、条漫（纵向连续滚动）；预加载前后 3 页（正向翻页前向优先，反向翻页后向优先，最多并发 3 张）。
- **进度记录与恢复（重要）**：记录阅读页码进度并缓存；下次打开**直接恢复到上次页码**（首次构建即定位，不从第一页开始）；条漫模式恢复页码显示。
- 支持双指缩放（`UIScrollView` / SwiftUI 缩放）。
- **弱网优化（重要）**：网络较差时点击漫画文件**先展示 UI 进入加载界面**（不阻塞、不出现「点了没反应、需长等」），加载期间防抖去重重复点击。
- **RAR/CBR**：使用 UnrarKit / libarchive 解析（原生库依赖）。

**漫画识别策略**：
1. 扩展名优先：`.cbz`/`.cbr` 直接按漫画处理。
2. 内容嗅探兜底：图片占比 ≥ 90% 且文件名呈自然序列判定为漫画。
3. 目录级约定：连接源可标记为「漫画库」。
4. 手动覆盖：长按菜单「以漫画阅读打开」。

| 音频后台 | AVAudioSession + MPNowPlayingInfoCenter | 锁屏/后台/控制中心 |
| **内容解析** | | |
| epub/zip/cbz | ZIPFoundation | 按需解包、单页流式读取 |
| rar/cbr | UnrarKit / libarchive | RAR 解析 |

### 4.2 关键决策对比

| 决策点 | 方案 A（推荐） | 方案 B | 结论 |
| --- | --- | --- | --- |
| 播放内核 | AVPlayer 硬解 + VLC/FFmpeg 软解双引擎 | 纯 AVPlayer | 双引擎覆盖全格式，符合 nPlayer 定位，选 A |

**要点**：
- **统一门面**：UI 只面向 `PlayerCore`，内部按格式路由到硬解/软解引擎，切换对上层透明。
- **数据源抽象**：本地与网络统一为可 Range 读取的数据源；网络源经边下边播缓存代理。
- **缓存**：分片下载 + 磁盘 LRU，支持 seek 定位与断点续播，容量可配可清理。

### 5.4 边下边播缓存流程

```
用户拖动进度到 t 秒
   │
   ▼
PlayerCore → ResourceLoaderProxy 请求 [offset, offset+len)
   │
   ├── 命中缓存 → 直接返回分片给解码器
   │
   └── 未命中 → StorageAdapter.readStream(range:) 发起 Range 请求
                 （WebDAV: HTTP Range；SMB: AMSMB2 分块读）
                 ↓ 下载分片
                 写入 SegmentCache（磁盘 LRU）
                 ↓
                 返回分片给解码器（同时预读后续窗口）
```

## 7. 风险与约束

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 软解（VLC/FFmpeg）包体积大 | IPA 增大数十 MB | 可接受；按 arm64 精简，或动态框架 |
| SMB 三方库兼容性（不同 NAS 实现差异） | 部分共享连接失败 | 使用成熟的 AMSMB2，做多品牌 NAS 兼容测试 |
| 边下边播 seek 频繁导致重复下载 | 流量/性能浪费 | 分片缓存 + 预读窗口 + 合并请求 |
| RAR 解析在 iOS 支持有限 | 部分漫画无法读取 | UnrarKit/libarchive；失败提示转 zip |
| 后台软解耗电/发热 | 体验下降 | 优先硬解，软解限制分辨率/提示；后台仅音频 |
| App Store 审核（浏览器/网络下载类） | 上架受阻 | 应用主体为个人内容中心，浏览器为附属；遵守隐私与 ATS |
| 大文件在弱网串流卡顿 | 播放体验差 | 自适应缓冲、超时重试、降级提示手动下载 |
| 纯本地无同步 | 多设备数据不共享 | 本期定位单设备；预留配置导入导出，未来可选 iCloud 同步 |
