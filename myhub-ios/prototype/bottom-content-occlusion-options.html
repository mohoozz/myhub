列表底部被悬浮页签栏遮挡 · 处理方案原型

涉及页面：阅读（ReadingHomeView）、浏览（BrowseHomeView 路径源 / BrowseDirectoryView 目录 / 收藏页同理）、设置（SettingsHomeView）。
每个方案给出「阅读列表 + 设置分组列表」两个场景，用于确认修复对列表型与分组型页面同时生效。

根因（现状）：页签栏在 TODO 376 方案 C 改为悬浮圆角胶囊、经 RootView 的 .safeAreaInset(edge: .bottom) 注入，同时设计为「内容可滚动穿过胶囊下方」。
但页面内的滚动容器（NavigationStack 里的 ScrollView / List）拿到的底部安全区只有 Home 指示条，并不包含这条胶囊（RootView 里已有同样结论：页面内 overlay 会落进页签栏之下，因此多选操作栏要靠 bottomChromeHeight 手动抬升）。
结果是：列表末尾没有为胶囊预留滚动空间 → 滚到底也再多滑不出 78pt，最后一行 / 最后一个选项永久停在胶囊下方，点击被胶囊拦截。
以前页签栏是物理 VStack 占位，内容天然让位，所以没有这个问题；文件越多、列表越长越容易踩到。

现状

Before

滚到底时，阅读列表最后一条记录、设置最后一项「关于 MyHub」都落在胶囊下方；胶囊是半透明玻璃，文字隐隐透出，看起来能点，实际被胶囊挡住。
还有一处不易察觉：胶囊四周的阴影会把压住的那一行盖得更糊，用户只能反复上滑尝试。

方案 A · 滚动内容末尾安全留白

已选定并实施

页面滚动容器末尾统一补一段 bottomChromeHeight + 12pt 的透明留白（ScrollView 用 safeAreaInset 占位、List 同法）， 滚到底时最后一行完整停在胶囊上沿上方 12pt，可正常点击。
内容仍然可以从胶囊下方穿过（玻璃透出、层次保留），现状视觉语言不变。
优点：改动最小、可封装成一个 ViewModifier 一次覆盖所有页面（含未来新页）；多选态胶囊隐藏时留白自动归零，与现有 bottomChromeHeight 体系天然对齐。
缺点：底部会多出约 12pt 空白；每页仍需挂一次修饰器（可接受）。

方案 B · 物理让位（内容截止在胶囊上沿）

结构最稳

把胶囊高度变成真正的布局占位：内容区域在胶囊上沿截止，胶囊下方 78pt 由页面底色垫底（不再有内容穿过）。
滚到底时最后一行紧贴胶囊上沿（可留 8pt），任何页面、任何滚动位置都不会出现内容与胶囊重叠。
优点：从结构上根除遮挡，不依赖每页自觉留白；阴影下不再有残影，观感更干净。
缺点：失去「内容从玻璃下穿过」的悬浮感；胶囊下方出现一条没有内容的底色带（白底上靠极浅灰/虚线分隔才不显空）。

方案 C · 页签栏改回贴底通栏

最系统

放弃悬浮胶囊，页签栏改回贴底通栏磨砂条 + 顶部 1pt 灰色分隔线（与系统 TabBar 同形态），内容区域截止在栏上沿，物理上不存在遮挡。
优点：问题零残留、实现最简单、适配任何内容；滚动条也在栏上方结束。
缺点：与已选定的 TODO 376 方案 C「悬浮圆角胶囊」视觉语言冲突，等于回退一次设计；mini 播放器需重新对齐为贴底通栏形态。

方案 D · 滚动时胶囊自动淡出（Safari 风）

体验向

在方案 A 的保底留白之上，再加一层滚动联动：页面上滑翻列表时胶囊淡出并下沉，停止滚动 0.8s 或回滑到顶部时淡入恢复； 这样滚动过程中底部可视区域最大，停下后胶囊仍在原位，最后一行也不会被挡。
优点：可视区域最大、最现代；各页已有滚动偏移探针（浏览页搜索框显隐就靠它）可直接复用。
缺点：交互多一层状态（滚动中 / 停止 / 多选态 / 沉浸态互相叠加），排查成本高；页签在滚动时短暂不可见，与「页签常驻」的习惯有偏差。

方案对比

方案遮挡是否根治观感影响改动范围风险
A 末尾安全留白是（滚到底可完整露出）几乎无，底部多 12pt 空白1 个 ViewModifier + 4~5 个页面挂载低；需注意与多选操作栏 inset 叠加（胶囊隐藏后高度归零，天然不冲突）
B 物理让位是（结构上不可能重叠）失去内容穿透玻璃的层次，底部多一条底色带RootView 布局方式 + 胶囊外层容器中；改动全局布局，所有页面底部视觉一起变
C 贴底通栏是回退悬浮胶囊设计BottomTabBar 样式 + mini 播放器对齐中；与 376 已确认方案冲突
D 滚动淡出是（含 A 的保底）滚动中页签不可见A + 各页滚动监听 + 全局状态较高；多状态叠加易出「闪一下」「收起不恢复」类 bug
已选定：方案 A（已实施，见 TODO 425）。它只补「本该存在但被悬浮布局漏掉」的底部滚动空间，不动已经确认的悬浮胶囊视觉，且能用 bottomChromeHeight 现成机制自动适配「多选态隐藏页签栏 / mini 播放器出现 / iPad 无页签栏」三种高度变化。
实现要点：新增 reservedBottomChrome(extra: 12) 修饰器，内部 @Environment(\\.bottomChromeHeight) + .safeAreaInset(edge: .bottom, spacing: 0) { Color.clear.frame(height: chrome + extra) }； 挂到 ReadingHomeView 的 ScrollView、BrowseHomeView 的源列表、BrowseDirectoryView 的目录 ScrollView、SettingsHomeView 的 List（以及收藏页）。 若选 B / C / D，我再按对应形态出更细的落地拆解。
