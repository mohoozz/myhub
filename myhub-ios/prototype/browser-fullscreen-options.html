内置浏览器 · 切底全屏 + 底部小胶囊

本次要解决三件事：①上下各留一段空白、网页实际可视面积比屏幕小；②胶囊标题要挪到屏幕最下方，且尺寸比现在小一圈（对齐 Safari 收起态）；③点胶囊展开的那一下有卡顿。

BrowserHomeView：根容器改 ZStack(alignment:.bottom)；网页层 .ignoresSafeArea(.container, edges: fullBleedEdges)（沉浸态 + 已加载网页时上下压满，起始页仍走安全区）；操作栏 / 小胶囊从 VStack 分栏改为 ZStack 兄弟浮层，网页高度不再随展开收起变化；immersiveBarGap = 8；新增 bottomChrome 单一出口 + @Namespace chromeMorphNS + chromeMorph 弹簧（response 0.34 / damping 0.86）；小胶囊改 28pt 视觉高 / 12pt 字 / 左右 11pt / 上下 8pt 透明热区（命中 44pt），底距补 +8pt 让视觉胶囊落到 8pt。

先说清空白的来源（实测当前沉浸态）：
iPhone 15（393×852）：顶部状态栏 59pt + 底部 8pt 外边距 + 34pt Home 指示条 = 42pt，网页只占中间 751pt，上下合计被吃掉 101pt（约 12%）。
根因是结构性的：网页在 VStack 里与操作栏上下分栏（操作栏占位 → 网页高度 852−59−34−8 再减去 60pt 条高／4pt 间距），而根容器本身没 ignoresSafeArea，于是上下安全区各留一条真空。
改法：网页层改为「全屏铺满 + 操作栏浮在网页之上」（Safari 的做法），导航层不再给浏览器留边距。

F1 · 网页全屏铺满 + 操作栏悬浮推荐

三、点击胶囊 → 展开的动画 A1–A3（下方为自动循环示意）

现在为什么"卡"？三个原因叠在一起：
①网页在跟着抖：操作栏在 VStack 里占位，它一出现网页高度就从 A 变到 B，WKWebView 每一帧都要重新布局 + 重绘，30fps 动画里等于把最贵的操作乘以 18 帧 —— 这是卡顿的主因，F1 把它改成就变成浮层（不占位）后，这条根因直接消失。
②两个视图各自做动画、还同时在屏：胶囊 .scale(0.6)+opacity 淡出、操作栏 .move(edge:.bottom)+opacity 淡入，两者中途重叠 → 一瞬间出现"一大一小两条"，眼睛读成闪跳。
③曲线不对：.appFast 是 150ms 的 easeOut，只够做"按压反馈"，做"形态变化"太短且没有回弹，收尾生硬。

A1 · 单容器形变（morph）+ 轻弹簧推荐

胶囊和操作栏不是两个视图，而是同一个浮层容器的两个状态：展开时宽 369×60（左右内缩 12pt），收起时 28pt 高的自适应小胶囊，居中。
切换只做三件事：改 frame（宽/高/圆角跟着插值 → 视觉上就是"长大成一条"）+ 内容交叉淡入（地址栏文字淡入、锁 + 域名淡出）+ 弹簧曲线 .spring(response: 0.34, dampingFraction: 0.86)。
优点：只有一个元素在动，不会有"两条同时在屏"的重叠；配上 F1 后网页不参与布局，全程 60fps；回弹收尾有 Safari 那种"弹一下坐住"的手感。
缺点：胶囊→操作栏中间态的宽度是插值出来的，地址栏字号要做等比缩放（1~2 行代码）。

A2 · 先收内容、再变尺寸（两段式）保守

第一段 90ms：操作栏内部控件整体淡出；第二段 180ms：容器从 60pt 收到 28pt，同时域名淡入。
优点：中间态不会有"半张脸"的字；纯 withAnimation 顺序控制，实现最直白。
缺点：两段加起来 270ms，比 A1 慢一档，体感"分两步走"，不如一次形变利落。

四、推荐组合与落点

项推荐为什么
布局F1 网页全屏 + 浮层操作栏唯一能同时解决"上下空白"和"展开卡顿主因"的方案；Safari 同款结构。
胶囊尺寸S1 28pt（热区仍 44pt）视觉小一圈对齐 Safari，手指命中不变。
胶囊位置贴 Home 指示条上方 8pt「挪到最下面」的极限位置；再低会压到系统 Home 指示条。
展开动画A1 单容器形变 + 弹簧 .34/0.86无重叠双影、网页不参与布局，全程顺滑。
改动落点（确认后执行）：
BrowserHomeView.swift —— contentArea 加 .ignoresSafeArea(edges:[.top,.bottom])；操作栏与胶囊从 VStack 内挪进 .overlay(alignment:.bottom)，合并为单容器形变； miniCapsule 28pt / 12pt 字 / 左右 11pt / 限宽 60% / 垂直 padding(8) 补热区；bottomBarGap 改 8（不再叠 phoneBottomChrome 的 8pt）。
RootView.swift —— phoneBottomChrome 的 .padding(.bottom, 8) 改为隐藏态取 0（仅影响 iPhone 浏览器沉浸态）。 Motion.swift 无需改，新曲线就地写在形变处。
不改动：收起/展开的触发逻辑（滑动/刷新收起、点击网页或胶囊展开）保持现状，仅换视觉与动效。
